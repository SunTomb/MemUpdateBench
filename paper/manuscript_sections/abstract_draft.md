# Abstract Draft

External-memory systems do not only accumulate information: they repeatedly revise it. Yet broad memory evaluations often conflate whether a final value remains recoverable, whether obsolete values remain stored, how compact the memory becomes, and whether a downstream answer model can use the resulting context. We introduce MemUpdateBench, a controlled diagnostic benchmark that isolates repeated updates to the same `(entity, attribute)` slot while varying update frequency and controlling same-name distractors and semantic near-miss `NOOP` events.

On the P6.3 hard update-frequency suite, the tested methods separate sharply along these dimensions. At `k=16`, Raw append and Heuristic CRUD retain perfect `slot_direct` state accuracy (1.00) but accumulate 14.25 and 7.44 stale same-slot entries and reach only 0.07/0.10 and 0.10/0.13 EM/F1 under `slot_prompt` answering. Long25 reduces stale burden to 1.13 and final memory size to 9.43, but its state accuracy falls to 0.91 and its prompted-answer score remains intermediate (0.48/0.53 EM/F1). Constrained CRUD removes stale same-slot burden and preserves state accuracy, yet still reaches only 0.70/0.70 EM/F1 at `k=16`, exposing a separate reader/answer-layer gap.

Additional diagnostics show that stale-context sensitivity depends on retrieval exposure, version metadata, ordering and answer-model choice; the qualified Qwen3.5-9B matrix remains nearly perfect, so the earlier stale-sensitive behavior is not universal across answer models. Bounded external-system probes further show why support envelopes and joint-pipeline provenance matter. MemUpdateBench is therefore a controlled diagnostic resource, not a universal memory leaderboard: its strongest conclusion is that final-state lookup alone is insufficient to characterize repeated-update memory behavior, while broader external validity remains an explicit next step.
