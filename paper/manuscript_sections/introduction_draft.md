# Introduction Draft

External memory gives language-model agents a mechanism for carrying user preferences, facts and task state across interactions. Most evaluations emphasize whether a relevant fact can be retrieved after it has been written. Deployment, however, is revision-heavy: users move, preferences change, deadlines are corrected and earlier statements become obsolete. The resulting problem is not simply retrieval of a final value. A memory system must preserve the current value, prevent obsolete values from contaminating later evidence, remain sufficiently compact, and support a downstream answer process that can interpret the retrieved context.

This paper studies one narrow stressor that is often hidden inside broader memory tasks: repeated updates to the same external-memory slot. MemUpdateBench represents a slot as `(entity, attribute)` and exposes updates through `ADD`, `UPDATE` and `NOOP` actions. Its controlled examples vary the number of target replacements while holding the task structure and distractor policy explicit. Same-name entities and semantic near-miss `NOOP` events make entity grounding and attribute parsing visible rather than allowing a system to succeed through surface matching alone.

The slot structure is intentionally restrictive. It makes it possible to measure four layers separately: final-state reliability, stale same-slot burden, memory compactness and slot-conditioned answer robustness. `slot_direct` asks whether a final value is recoverable under exact slot resolution; `slot_prompt` asks whether a reader can answer from the memory context. The first is an oracle-like state diagnostic, not an end-user answer score. The distinction is central: a memory can retain the final value while also exposing obsolete values that confuse a reader, and a compact manager can remove stale entries while missing the final update.

Our main controlled results demonstrate this separation rather than a single winning method. At `k=16` on the P6.3 hard split, Raw append and Heuristic CRUD retain state accuracy 1.00 but reach only 0.07/0.10 and 0.10/0.13 EM/F1 under prompted answering, with stale burdens of 14.25 and 7.44. Long25 reduces stale burden to 1.13 and final memory size to 9.43, but state accuracy falls to 0.91. Constrained CRUD has perfect state accuracy and no stale burden yet reaches only 0.70/0.70 EM/F1, indicating a residual answer-layer gap even when the state diagnostic is clean.

We then place these findings in a deliberately bounded external-validity program. Stale-context and version-arbitration diagnostics show that answer behavior depends on retrieval exposure, metadata, order and the answer model; a qualified Qwen3.5-9B matrix provides an explicit boundary to earlier stale-sensitive controls. External-system rows are reported with their support envelopes and joint-pipeline provenance rather than as an unconditional leaderboard. A native Graphiti development screen is formally INCONCLUSIVE for the prespecified current-value degradation claim, and a separately approved historical-serving follow-up was technically completed but classified BLOCKED by its conservative semantic attribution gate. Neither outcome is converted into zero accuracy or a universal system claim.

The contribution is therefore a controlled diagnostic benchmark and evidence framework for repeated same-slot updates. It makes state, lifecycle, retrieval and answer layers jointly inspectable while preserving the boundaries between engineering release, capability preflight, external joint-pipeline performance and native-system scientific evidence. The benchmark is intended to complement broad long-term memory evaluations, not replace them.
